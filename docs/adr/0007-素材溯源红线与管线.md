# 素材溯源红线与管线

T3（素材管线）回炉的决策记录之一。一期 T3 未经讨论落地：规划里没有对应的验收项，也没有 ADR，素材的来源、版本、是否修改只能靠人相信。2026-09-23 项目主要求回炉，本文收录回炉 grill 会话（三轮 25 题）中**工程层**的定案；内容层与 AI 生成素材见 [ADR-0008](0008-素材内容层与AI生成素材.md)。事实依据见 `docs/research/07`（来源与授权）、`docs/research/09`（管线工程实践）。

## 决定

### A. 红线与验收

1. **素材溯源升为第四条红线。** `public/assets/` 下每个文件都必须能被脚本回答三问：来自哪里（来源 + 版本）、什么许可、有没有被改过。任一问答不上，`npm run check` 变红。写进 CONTRIBUTING 红线节与 AGENTS.md。理由是星屿的信任叙事：零收集、纯静态、代码公开都可查证，素材是唯一一处"说它来自 OpenMoji，别人只能信"的地方；措辞与零收集两条红线已有机器强制，素材不该例外。ADR-0006 决定 13 已判过：人工同步约定是最易腐烂的约定。
2. **一期"素材"项标为回炉未收口，T3 按下表重新验收，全过之后才打 v0.1.0。** 允许顺延，不降验收；本次是把当初定得过低的标尺抬高。

   | # | T3 回炉验收项 | 判定方式 |
   |---|---|---|
   | 1 | `npm run check` 全绿；素材校验覆盖目录全覆盖、无悬空记录、哈希一致、来源不可变、许可白名单、NC 隔离、修改标记自洽、代码引用存在、署名由清单生成、SVG 无脚本和外链 | 机器 |
   | 2 | 拉取脚本按钉住的 commit 重取全部上游素材，与仓库逐字节一致，执行记录写进 devlog | 机器 + 记录 |
   | 3 | 构建产物含离线署名页，家长区可达；CREDITS.md 由清单生成 | 机器 |
   | 4 | 星灵、海岛以 SVG 文件入库并按 CC BY-SA 4.0 登记；星星进度图形按 MIT 代码记录 | 机器 |
   | 5 | 题库不因强度或画风泄题（ADR-0008 决定 6） | 不变量测试 |
   | 6 | 词库、ADR 指针、核查清单、CONTRIBUTING 红线节与 PR 检查单、旧调研报告勘误块已更新 | 人工核对 |

### B. 管线

3. **上游素材删掉重取，按钉住的 commit 拉取，产物进仓库。** 进仓库的字节就是家长加载的字节，中间没有构建期黑盒；任何人重跑拉取脚本都得到同样的字节。钉版本：OpenMoji `17.0.0`（commit `f9fc506a3f913be9897ab0181d611d4c910a4104`），Twemoji `v17.0.3`（commit `b6b55fef1e8636b540a6d016a4729ca8cdf2e60b`）。拉取地址用 commit SHA 而不用 tag，tag 可以被改指，与 ADR-0006 决定 4 钉 action SHA 同一逻辑。钉版有实际意义：OpenMoji 14→15 之间本项目用到的 14 个文件里有 3 个字节变了，其中 26C8 在深色底上约 5% 像素不同；15→17 不变（研 09 §4.2）。一期的 24 个文件与上述两个 commit 逐字节一致，重取不引起任何画面变化。上游升级只在每期收口时集中做，与 ADR-0005 决定 8、ADR-0006 决定 4 同节奏。
4. **接口按 150–300 个素材设计，实现按当前规模。** 清单结构、校验脚本能承载 300 条；不做 sprite、SVGO、分包。记录在案的冲突：优化即修改。CC 4.0 §3(a)(1)(B) 要求标明修改，且不以构成改编为前提（研 09 §5）；将来一旦引入任何处理，清单必须同时记录上游原始哈希与交付文件哈希，并写明修改说明。
5. **溯源清单与语义表分开，按路径对接。**
   - **溯源清单** `src/asset-manifest.json`：来源表（仓库、钉住的版本与 commit、许可、署名原文及出处）与逐文件记录（路径、类别 `fetched`/`authored`、上游路径、SHA-256、修改记录；自制与 AI 素材另记制作方式、作者、日期与生成记录）。许可在来源表里声明一次，条目继承。
   - **语义表** `src/game/catalog.json`：表情卡的情绪、强度、面部线索与验证结果，情境图的常见感受、替代文字与题面；由 `src/game/emotions.ts` 读取。
   - 两表的变更原因与读者都不同：溯源清单随上游版本变，给校验脚本和署名用；语义表随课程与评分变，给玩法用。不变量核对两表互相覆盖。
   - REUSE 规范不作单一来源：它没有 Node 实现，也没有记录来源、版本、哈希的字段（研 09 §1）；需要时可由清单生成 REUSE.toml。
6. **校验离线、重取核对手动。** `scripts/check-assets.mjs` 进 `npm run check`，只读本地文件、不联网，结果只取决于仓库内容；`scripts/fetch-assets.mjs` 联网，从钉住的 commit 重取并核对，每期收口时手动运行。`.gitattributes` 让 `public/assets/` 豁免换行符转换：仓库默认 `eol=lf` 会把上游的 CRLF 文件悄悄改成 LF，哈希随之对不上（研 09 实测 FxEmoji 即是 CRLF）。
7. **自制素材换载体。** 星灵、海岛从 `.tsx` 内联 SVG 抽成 `public/assets/original/mascot.svg`、`island-scene.svg`，按 CC BY-SA 4.0 登记，图形本身不改动。星星进度图形的亮灭是交互状态，它是 UI 代码，随代码按 MIT。修的是载体不是意图：同一份字节挂两个许可、且 ShareAlike 在 MIT 文件上无法执行，与"可查证"的姿态不符。两图随开发一期提交 `d1136dc` 入库，该提交由项目主与 Claude 共同署名，溯源清单如实把制作方式记为 `assisted`（人提出设计、AI 协助编写矢量代码）；ADR-0008 决定 9 的 CC0 规则只约束 AI 图像生成器的产出（`ai`）。
8. **应用内署名页。** 部署产物里原本没有任何署名字符（研 09 §6.4 实测），网站也不链接 CREDITS.md；按 CC 4.0 §3(a)(2) 的"媒介合理"，只靠仓库署名对网页这条分发链路不够。家长区"给家长"页加"素材署名"一节，内容由清单在构建前生成、随包离线，链接只作文本显示；有 AI 生成的图时一并列明。OpenMoji、Twemoji 的署名要求原文都点名应用的"About"一类位置。

### C. 文档与流程

9. **CREDITS.md 与应用内署名数据由清单生成，check 核对不漂移。** 与免责声明"单一来源 + 机器校验"同构（ADR-0006 决定 13）。贡献流程随之改为：改清单，运行生成脚本，不手改 CREDITS。
10. **决策拆成两份 ADR，旧调研报告只加勘误块。** 本文管管线与红线，定下来就稳定；内容层与 AI 路线会随原型结果和机构反馈再改，放 ADR-0008。旧报告（研 01、03、05）不改正文，在文首加勘误块指向研 07、08；研 04 缺 AI 生成内容与未成年人内容分类的规则，文末补一节；保留原貌，才看得出当初依据的是什么。研 02 对 CAFE 的记载核实无误，不加勘误（grill 第二轮 Q18 转述的"研 02 误读 CC BY"来自研 07 初稿的笔误，已更正）。ADR-0002、0003、0006 各加一行指针，说明哪部分被修订。

## Considered Options

- **维持 PR 人工"准入四问"**，或只加校验脚本、不升格为红线：素材是三条红线里唯一没有机器强制的，又是风险表明列的五大风险之一，拒绝。
- **就地为现有 24 个文件补元数据**：只能记录"我相信它来自哪"，建立不了可复现，拒绝。
- **构建期从 npm 包抽取素材**：进仓库的字节与家长加载的字节之间多一道构建黑盒，违背可审计姿态，拒绝。
- **按 24–40 个素材设计**，规模到了再重构：清单的形状现在就能定对，重构成本高于提前定形；**现在就上 sprite、SVGO、分包**：为想象中的性能问题付真实的复杂度，且与"未修改"直接冲突，拒绝。
- **自制素材全部抽成文件**（含星星）：丢失亮灭状态；**维持内联、CREDITS 改写为双许可声明**：ShareAlike 在 MIT 文件上执行不了，拒绝。
- **溯源清单与语义表合成一张表**，或**映射表维持硬编码、只加溯源清单**：前者混淆两种变更原因，后者装不下验证结果，拒绝。
- **应用内只放一个跳往 GitHub CREDITS 的链接**：要离开应用、依赖外部站点，拒绝。
- **合成一份 ADR**；**直接改旧报告正文**：见决定 10，拒绝。
- **一期连 AI 素材一起做完再收口**：AI 素材集连同评分依赖机构渠道招人，工作量与不确定性大，推迟到二期新任务 T13（ADR-0008 决定 16）。

## Consequences

- 四条红线都有机器强制；`npm run check` 的覆盖面从措辞、免责声明、类型、逻辑扩展到素材溯源。
- 家长在应用里看到的署名与仓库里的 CREDITS.md 出自同一份清单，不会漂移。
- 钉版意味着上游修图不会自动进来，升级是每期收口的一项人工动作；拉取核对依赖 raw.githubusercontent.com 可达，故只在收口时手动跑，不进 CI。
- 被撤下的素材在 git 历史里仍然可见：main 禁强推（ADR-0006 决定 6），历史不重写。ADR-0008 的下架承诺据此如实表述。
- 代价：多两个脚本、两个数据文件、两个生成物；清单体积随素材增长，300 条时可按来源拆分文件，校验逻辑不变。
