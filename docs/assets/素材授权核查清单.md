### NC（非商业）素材政策

**允许进库，但必须隔离**（ADR-0006 决定 10，现由素材校验机器强制）。采用 NC 素材时五件事缺一不可：

1. **目录隔离**：放进 `public/assets/nc/<来源>/`，不与可商用素材混放；
2. **不合成**：不得与 BY-SA 素材合成同一张图；
3. **清单与署名**：在溯源清单登记该来源，CREDITS.md 由清单生成时会自动标出 NC 状态；
4. **README 许可节声明**："本仓库含 CC BY-NC-SA 素材，整体分发不得用于商业用途"；
5. **准入五问**照过，并在 PR 中说明为什么无 NC 的来源（首选 Mulberry）不能满足需求。

**已知代价**：NC 的"非商业"没有清晰法律边界；NC 会传染整体分发，fork 星屿的人也一并受限。这是"有需要才用"的通道，不是默认选项。

## 三、真人面孔与不可入库的来源

依据研 07 §一、§三。

1. **科研表情库全部不可用**：已核 7 个真人表情库，6 个限科研或限授权研究者（KDEF 明文点名 apps，JAFFE 明文点名 GitHub，NimStim、RaFD、CFD、CAFE 同样受限）。CAFE 页面上的 CC BY 一处是论文的文章许可、一处是网站模板页脚，都不是图像许可。唯一 CC BY 4.0 的 Face Research Lab London Set 只有成人、只有中性与微笑，模特同意书也只涉及研究用途，不建议入库。
2. **图库照片（Unsplash、Pexels 类）不采用**：许可禁止把未修改照片汇编再分发；儿童肖像风险高。
3. **插画站只能由人眼参考风格，不入库，也不作 AI 输入**：unDraw、Storyset（条款 §6）、DrawKit 都禁止成包、汇编或数据库式再分发，放进开源仓库即落入此类；unDraw 与 DrawKit 还明文禁止任何 AI 用途（DrawKit 点名 "image generation tools"）。
4. **真人照片不入库，也不作任何 AI 生成的参考图或输入**：儿童照片受个人信息保护法第 28 条（不满 14 周岁的个人信息为敏感个人信息）与民法典第 1019、1022 条约束，fork 里的副本删不掉。真人只来自家长本地导入：只存在本机、只供这位家长使用（ADR-0008 决定 14）。
5. **机构合作拍摄**（远期）：若机构有意愿，可探讨签署授权的志愿者表情照片集，列入机构访谈的合作探询话题池，不做前置依赖。

## 四、目录与命名规范

```
public/assets/
├── emotions/
│   ├── openmoji/1F604.svg   ← 上游码点原名（大写 = OpenMoji 惯例）
│   └── twemoji/1f604.svg    ← 上游码点原名（小写 = Twemoji 惯例）
├── scenes/
│   └── openmoji/1F381.svg
├── original/                ← 非 AI 生成的自制内容素材（目前没有），kebab-case 命名
├── ai/                      ← AI 生成素材（CC0 1.0），随 T13 启用
└── nc/<来源>/               ← NC 素材隔离目录
```

- 每个来源在溯源清单的来源表里登记自己的目录；文件不在其来源登记的目录下，校验就红。
- 上游文件保持原名、原字节；语义（"这是高兴 · 高强度"）只写在语义表 `src/game/catalog.json` 里。
- 素材目录豁免仓库的换行符转换，按字节原样保存。
- 界面图形不放在这里：它们是前端代码，写在 `src/` 的组件里。

## 五、新素材准入五问（PR 检查项）

1. **许可**明确允许再分发 + 修改 + 开源打包吗？找不到许可原文就不进；聚合站的许可标注不可照抄，一律回溯上游原文。
2. 与仓库现有素材的许可**兼容**吗？SA 传染方向核对过吗？NC 素材隔离目录、且没有与 BY-SA 素材合成吗？
3. 已**登记进溯源清单**（来源、钉住的 commit 或原件哈希、许可、修改记录），并运行 `npm run assets:credits` 生成了署名吗？
4. 内容过了**年龄中性自查**（ADR-0003）与 4–8 岁最严内容标准（研 04 §五）吗？高强度的生气、害怕是否"清楚但不吓人"，情境题材是否不含危险动作、不放大嘲讽（ADR-0008 决定 6、7）？
5. **AI 生成素材**另答：生成器在准入名单上吗？画中人物虚构、提示词未点名任何真人、未用真人照片作参考或输入吗？卡片带"AI 生成"标识、生成器原件已存档吗？要进语义表的，效度验证过了吗？（详见 §六）

## 六、AI 生成素材

依据 ADR-0008 决定 8–13、研 10。

- **生成器准入**：只看条款，不看中国大陆能否使用。准入条件：产出归用户或平台不主张权利；允许以 CC0 公开再分发，没有 NC、地域或下游训练限制；内容政策允许非性化的儿童形象；不禁止管线里的必要处理。当前名单以 `scripts/check-assets.mjs` 的 `GENERATORS` 为准，首批见 ADR-0008 决定 13 的表；新增要提 PR，引用条款原文。
- **许可**：AI 图像生成器的产出按 CC0 1.0 发布，放在 `public/assets/ai/`，登记在来源 `starry-isle-ai` 下。
- **清单必填**：生成器、模型、条款地址与核对日期、提示词与撰写人、生成时间、IPTC Digital Source Type；原件的哈希、格式与存档位置；后处理步骤；审核人、日期与两项声明（人物虚构、未用真人照片作输入）。缺一项校验就红。
- **标识**：家长看得到的页面都写明；每张 AI 卡在图片区域外的边框角加统一的"AI 生成"标记。不自行裁掉生成器的水印，改用平台自带的无水印选项或本地生成（研 10 §2：深度合成规定第 18 条没有"恶意"要件）。
- **格式与原件**：交付 512 见方的有损 WebP，不矢量化；交付件保留生成器写入的 XMP 标识；生成器原件连同元数据按批次作为 GitHub Release 附件存档。
- **效度验证**：进语义表之前，至少 20 名成人匿名评分；高、中档命中率不低于 75%，低档显著高于猜中率且没有集中误判，强度各档要拉开（ADR-0008 决定 8）。评分用交付件做。
- **下架**：任何人认为某张图像真实的孩子，发邮件到 starry-isle@outlook.com，不要求举证，收到即从当前版本和网站撤下；git 历史里的旧版本删不掉。
