## 三、真人表情照片：核查结论（一期定论）

难度递进的"真人照片"档**不打包任何照片数据集**：

1. **科研表情库全部不可用**：NimStim、KDEF、CAFE（儿童表情库）、RAF-DB 等标准化表情库的许可一律为"仅限科研使用、禁止再分发"——开源仓库打包分发直接违约（研 02 §3.3 已核查）。
2. **图库照片（Unsplash/Pexels 类）不采用**：其许可禁止把未修改照片再编译分发为素材集；且儿童肖像风险高（肖像权、被撤回风险），一张都不进仓库。
3. **落地路线 = 家长本地导入**（Autimo 已验证的玩法，研 02）：真人档由家长在设备上现场拍摄/选择自家人的照片，**纯本地使用、不上传、默认不留存**——与 ADR-0004 零收集架构互相成全。一期以共玩回合（家长真人做表情）承担"真人档"，照片导入功能排开发二期评估。
4. **机构合作拍摄**（远期）：若机构验证期有意愿，可探讨签署授权的志愿者表情照片集，按 CC BY-SA 发布——列入机构访谈的"合作探询"话题池，不做前置依赖。

## 四、目录与命名规范

```
public/assets/
├── emotions/
│   ├── openmoji/1F604.svg   ← 上游码点原名（大写=OpenMoji 惯例）
│   └── twemoji/1f604.svg    ← 上游码点原名（小写=Twemoji 惯例）
├── scenes/
│   └── openmoji/1F381.svg
└── (自制素材按 original/<主题>/ 存放，kebab-case 命名)
```

- 语义（"这是高兴-高强度"）只写在 `src/game/emotions.ts` 的映射表里，素材文件不改名。
- 自制素材（美术样张、星灵角色、UI 图形）以 **CC BY-SA 4.0** 发布（与 OpenMoji 同向，允许社区主题包沿用）；在 CREDITS.md 逐条登记。

## 五、新素材准入四问（PR 检查项）

1. 许可明确允许**再分发 + 修改 + 开源打包**吗？（找不到许可原文 = 不进）
2. 与仓库现有素材的许可**兼容**吗？（SA 传染方向核对过？NC 素材已隔离目录？）
3. **署名**已按该来源的指定格式写进 `CREDITS.md` 了吗？
4. 内容过**年龄中性自查**（ADR-0003）与 4-8 岁最严内容标准（研 04 §五）了吗？
