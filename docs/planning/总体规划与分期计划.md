# 星屿总体规划与分期计划

v1 · 2026-09-10 · 调研期收口产出。**验收标准是进度的准绳，时间只是参考**（单人开发：允许顺延，不允许降验收）。任务在开发一期工程化后转为 GitHub Issues 跟踪。

v1.1 · 2026-09-27 · T3 回炉（ADR-0007、ADR-0008）：一期"素材"项回炉未收口，T3 验收重写；二期新增 T13 AI 素材集；backlog 增加家长本地导入与两个研究项。

## 一、定位与设计原则

**定位**：免费开源、中文、面向 4-8 岁发展阶段（准入按能力）孤独症儿童的情绪认知辅助训练应用；核心玩法内置泛化机制与家长共玩；对外不自称"游戏"、不宣称疗效、零数据收集。

**设计原则**（每个玩法、每期验收逐条过）：

1. **循证优先**：玩法对齐已验证的课程结构（15 种情绪清单、四通道进阶，见报告 01/02；递进顺序按研 08 §3 的发展常模，15 种情绪的"经验证顺序"没有一手出处），不发明无依据的训练法。
2. **泛化不可妥协**（ADR-0002）：每个玩法 ≥1 项泛化机制（共玩回合、线下迁移任务、家长本地照片；AI 生成的写实人像不单独算，ADR-0008）。
3. **家长是玩法角色**：共玩而非托管（词库"家长"）。
4. **年龄中性美术**（ADR-0003）：星空/海岛/几何感生物，无低幼卡通与娃娃音文案。
5. **优雅结束与克制奖励**（报告 03 + 未保法 74 条）：回合上限、结束预告、收尾仪式；不做签到/连击/排行榜/开箱。
6. **合规底线**（ADR-0004）：对外措辞过禁语清单、零收集、不做筛查评估。

## 四、开发一期：工程底座 + 垂直切片（参考 7 天）

**任务**：

- **T1 技术选型（ADR-0005）**：硬约束 = 纯静态前端、无服务器依赖、可离线（PWA 方向）、开源技术栈、目标设备为家用平板/手机浏览器。候选：Phaser / PixiJS / Godot HTML5 导出 / Canvas+轻框架。选型前做 ≤1 天的触摸交互 spike。
- **T2 仓库工程化**：公开 repo；License 决定（代码与美术素材分开授权，素材需兼容 ARASAAC/Mulberry 的 NC 条款）；README（含免责声明，三处同文之一）；CI（构建+静态站部署）；CONTRIBUTING 雏形。
- **T3 素材管线**：表情素材来源与授权核查清单（OpenMoji/Twemoji + 真人表情开源数据集），统一命名目录。**2026-09-27 回炉**（ADR-0007）：一期交付物既无验收项也无 ADR，素材的来源与版本无从查证。回炉后素材溯源升为第四条红线；上游素材按钉住的 commit 重取；溯源清单、语义表与校验脚本进 `npm run check`；应用内加素材署名；验收见下方"T3 回炉验收"。真人表情开源数据集一条经研 07 核实不可行。
- **T4 玩法 P1"认表情"**：高兴/难过/生气/害怕四基础情绪识别，难度递进雏形（卡通 → 真人照片 → 情境）。2026-09-27 注：真人一端由家长共玩承担，完整的刺激阶梯见 ADR-0008 决定 1。
- **T5 泛化机制雏形**：P1 内置屏外共玩回合（如"家长做表情、孩子来猜"的提示环节）。
- **T6 结束仪式雏形**：回合上限 + 结束预告 + 收尾动画。

**验收标准**（全过才收口）：

- [ ] 陌生设备浏览器打开即玩：无安装、无账号、无联网依赖（离线缓存可后移二期）
- [ ] P1 完整可玩，且含 ≥1 次屏外共玩回合
- [ ] DevTools 复核：除静态资源外零网络请求，无埋点、无第三方 SDK
- [ ] ADR-0005 成文；README 免责声明就位并过禁语自查（对照报告 04）
- [ ] P1 过泛化机制检查项（原则 2）
- [ ] 美术样张 1 套，过年龄中性自查（原则 4）
- [ ] T3 回炉验收六项全过（ADR-0007 决定 2），全过之后才打 v0.1.0：
  - [ ] `npm run check` 全绿；素材校验覆盖目录全覆盖、无悬空记录、哈希一致、来源不可变、许可白名单、NC 隔离、修改标记自洽、代码引用存在、署名由清单生成、SVG 无脚本和外链
  - [ ] 拉取脚本按钉住的 commit 重取全部上游素材，与仓库逐字节一致，执行记录写进 devlog
  - [ ] 构建产物含离线署名页，家长区可达；CREDITS.md 由清单生成

  - [ ] 题库不因强度或画风泄题（不变量测试）

## 五、开发二期：最小核心循环（参考 7 天）

**任务**：

- **T7 星屿世界壳**：岛屿地图作为玩法入口；进度以"探索度"呈现，不用分数排行。
- **T8 玩法 P2"情绪配情境"**（表情 ↔ 引发情境匹配）；P3"表达模仿"为可选（前置摄像头镜像、纯本地不留存——涉权限文案须在家长页说明，做不完就砍）。情境图按 ADR-0008 决定 7 制作：画出事件中的主角，主角的脸背对镜头或在画外，题材逐张对照未成年人网络信息分类办法自查，并放大显示。
- **T9 反馈与家长视图雏形**：回合摘要用家长语言（练了什么、屏下建议）；本地存储进度 + 导出（JSON/图片）。
- **T10 线下迁移任务卡**：每玩法结束生成一张"带下屏"小任务（如"今天找一次爸爸的生气表情"）。
- **T11 家长说明页**：定位（合规措辞）、共玩指南、免责声明（三处同文之二）、屏幕时间 FAQ。
- **T12 分发**：静态托管定案并部署（境内托管需 ICP 备案 vs GitHub Pages 免备案但境内访问不稳，二选一）；自愿标注适龄提示。
- **T13 AI 素材集**（ADR-0008）：插画层与写实层表情卡，首批高兴、难过、生气、害怕 × 3 档，生气、害怕补齐低强度档；插画层起步 4 个混龄身份，写实层的身份数在开工时定；按生成器准入名单离线生成，守防撞脸规矩；每张卡过成人评分效度验证后才进题库；交付 512 见方 WebP，生成器原件按批次存档；情境图的生产与 T8 共用这条流程。开工前先 grill ADR-0008 决定 17 列出的延后事项。

**验收标准**：

- [ ] 核心循环走通：进岛 → 选玩法 → 游玩 → 反馈 → 家长视图 → 线下任务卡
- [ ] ≥2 个玩法过泛化检查项
- [ ] 优雅结束机制全局生效；无沉迷设计自查通过（原则 5）
- [ ] 家长说明页过禁语清单自查
- [ ] 有可分享 URL，平板 + 手机真机实测通过
- [ ] 本地进度保存与导出可用
- [ ] T13 的验收在开工 grill 时定案；底线由 ADR-0008 与素材校验保证：进题库的 AI 卡全部验证过、带 AI 标识、生成记录完整

## 六、机构验证期（穿插）

- 轻访谈（提纲：docs/research/06）→ 结论回填 05"待确认"节
- demo 回访（二期收口后）：干预师上手 P1/P2，记录修改意见与"是否愿意推荐给家长"的真实回答

## 七、后续期 backlog（按优先级）

1. 按机构反馈迭代玩法与素材
2. 情绪课程完整递进（15 种情绪路线图，借鉴 Transporters/EmotiPlay 的清单；顺序按研 08 §3 的发展常模：高兴，难过或生气，害怕或惊讶，厌恶，复杂情绪从"骄傲"起，羞愧等社会情绪放进情境题）
3. 社交互动领域玩法群（社交故事、情境模拟——ADR-0001 二期方向）
4. 主题包机制（大龄题材，ADR-0003 预留口）
5. 社区化建设：招募贡献者、devlog 公开（对策"单点维护死亡"）
6. AAC 生态协作（Cboard/AsTeRICS Grid 中文化贡献，双向引流）
7. 云同步（前置：报告 04"加云功能前"7 项义务全部完成）
8. 家长本地导入照片（ADR-0008 决定 14，排在 T13 之后）：约束已定，照片只存在本机浏览器里，不上传，不送进任何生成器，只有这位家长能用，一键可删
9. 研究项，不排期（ADR-0008 决定 15）：家长照片经同意后云端公开；实时生成接口。两者都与 ADR-0004 冲突，启动前必须先另立 ADR 修订 ADR-0004

## 八、风险与对策

| 风险 | 证据 | 对策 |
|------|------|------|
| 单点维护死亡（LetMeTalk 模式） | 报告 02 | 纯静态零后端零运维；文档齐全降接手门槛；社区化；机构合作提供外部动力 |
| 泛化失败，沦为"电子卡片" | 报告 01/03 | ADR-0002 检查项进每期验收；机构验证期实测 |
| 合规踩线 | 报告 04 | ADR-0004；每期验收含禁语/零收集自查；商店上架前过报告 04 行动清单 |
| 素材版权 | 报告 02、07、10 | 素材溯源红线机器校验（ADR-0007）；生成器准入名单与防撞脸规矩（ADR-0008）；NC 隔离且不与 BY-SA 合成 |
| AI 素材表达不准 | 报告 08 §7：AI 生成的害怕、厌恶最不可靠 | 成人评分效度验证是进题库的前置条件（ADR-0008 决定 8）；负面情绪多备候选、重点筛 |
| 单人精力耗竭 | 报告 03 的家长版本，同样适用开发者 | 时间盒；顺延不降验收；backlog 无情砍；每期收口即是一个可停靠的完成态 |

任务转 GitHub Issues/Projects（T2 后）；每期收口写一篇公开 devlog——过程透明本身就是公益项目的信任资产。
