# Spike：触摸交互验证（ADR-0005 前置）

**日期**：2026-09-10 ｜ **时间盒**：≤1 天 ｜ **状态**：桌面浏览器自测通过，真机清单待过

## 问题

"认表情"玩法的核心交互是"大卡片点选 + 温和反馈动画 + 星星进度"。这类交互是否必须上游戏引擎（Phaser/PixiJS/Godot），还是纯 DOM + CSS 动画就够？

## 做法

零依赖单文件 `index.html`（双击可开，无需构建），覆盖六个验证点：

1. 系统字体栈 + 全内联资源 → 零网络请求；
2. `touch-action: manipulation` → 消除双击缩放与点击延迟；
3. ≥140px 高的大触摸卡片（远超 WCAG 2.5.5 的 44px 底线）；
4. 选中光晕 / 星星点亮动画全部走 `transform`/`opacity`（合成层，不触发重排）；
5. `prefers-reduced-motion` 自动关动画（感官友好硬需求）;
6. Web Audio 正弦波合成温和提示音（零音频素材；验证 iOS 手势解锁路径）。

页面内置 `pointerdown → 渲染完成` 耗时日志，作为响应延迟的量化证据。

## 结论（桌面自测）

- Chrome/Edge 桌面模拟触摸：点选响应耗时 <20ms，动画满帧，无布局抖动。
- 交互复杂度评估：P1 玩法全部交互（点选、进度、插页、收尾动画）都在本 spike 已验证的能力范围内，**不需要 canvas 逐帧渲染**。
- DOM 方案独有收益：原生可访问性（焦点、系统字号、屏幕阅读器）、中文排版免字体打包、`prefers-reduced-motion` 免费拿到。

→ 选型定论与备选比较见 `docs/adr/0005-技术选型DOM优先不用游戏引擎.md`。
